# ADR-0041 · An adjoint gradient for the flow split, from the open-source adjoint solver

**Status:** proposed · 2026-11-15 · lifts ADR-0040 decision 2's "finite differences only" for `flow_split`; builds on ADR-0038 (decisions 4, 5 and 7) and ADR-0040 (decisions 4, 6 and 7)

## Context

ADR-0040 made the flow split (J = Σᵢ (Qᵢ/Q − 1/N)² over the outlets) an objective with finite differences only: N + 1 solves per cycle (16 solves and 84 minutes for the three-height manifold). Foundation's `adjointShapeOptimisationFoam` cannot give its gradient, because its outlet conditions hard-code the pressure loss. The open-source adjoint (`of14-adjoint`, ADR-0038 decision 7; a separate GPL program driven only through files and argv) can take an objective of its own. The derivation (Othmer's adjoint in this code base's sign convention, Ua = −u, pa = −q) gives, for the flow split: Ua = 0 at a velocity inlet (J does not depend on the pressure); at outlet i, pa = Ua·U + Ua_n U_n + ν_eff ∂(Ua_n)/∂n − cᵢ with cᵢ = dJ/dQᵢ = (2/Q)(eᵢ − Σₖ eₖ fₖ), eᵢ = fᵢ − 1/N, and a Robin tangential condition; the wall sensitivity s = ν_eff (∂U/∂n)·(∂Ua/∂n) is unchanged. The design is in the T0 note of 2026-11-15 (Phase B).

## Decision

1. **The objective picks the program.** Engine `of14.adjoint` stays one engine (label "OpenFOAM 14 · Adjoint (laminar)"); `pressure_loss` keeps Foundation's `adjointShapeOptimisationFoam` byte for byte (golden `tests/golden/compile/of14/adjoint_pressure_loss`, written by the writer before this change), and `flow_split` runs `adjointFoam`. There is no user-facing solver switch.
2. **Snapshot and settings.** `SolveSnapshot` gains `adjoint_objective` (`pressure_loss` | `flow_split`) and `adjoint_outlets` (patch names; empty is every pressure outlet), filled by `build_solve_snapshot` for the adjoint engine only, from two hidden parameters of `/solver/settings` (`adjoint_objective` enumeration, `adjoint_outlets` JSON list of distinct names) that `solve.configure` sets. Both enter the case basis only away from their defaults, so every earlier run keeps its basis.
3. **The flow-split case** (`stokes.compile.of14.adjoint`, pure functions): `controlDict` names `adjointFoam`; the job's argv is `["adjointFoam"]`; `0/Ua` is `fixedValue uniform (0 0 0)` at the inlets and `objectiveOutletVelocity` at the outlets, `0/pa` `objectiveOutletPressure` at the outlets; `system/adjointDict` holds `porosity false; sensitivity true;`, the `objective` block (`type flowRatePartition; outletPatches (...); targetFractions (1/N ...); viscousTerm true; tangential robin;`) and `ATC { type UaGradU; }`. Schemes, solvers, relaxation and residual control are the pressure-loss case's. Golden: `tests/golden/compile/of14/adjoint_flow_split`.
4. **Every pressure outlet is in the split (G31, decided by the owner 2026-11-15).** The writer refuses (`compile.unsupported`) fewer than two outlets, a name that is not a pressure outlet, and **a pressure outlet left out**: an outlet outside the objective would need an adjoint condition of its own (the same condition with cᵢ = 0), which the solver does not set up. `shape.optimise` refuses that case before meshing and names the outlet; `shape.check` falls back to finite differences alone. Finite differences accept any subset of two or more outlets.
5. **The program is probed, not assumed.** `adjointFoam` joins the agent's allow-lists (`jobs.ALLOWED_UTILITIES`, `engine_env.UTILITIES`, `flags.ALLOWED_FLAGS` with no flags, the imported-case lists). `shape.gradients` reports, from the cached host probe of the host a cycle runs on, which gradient sources each objective may use and, for the flow split's adjoint, whether `adjointFoam` was found and why not. `gradient: adjoint` for `flow_split` is accepted only when it was found; otherwise `shape.optimise` raises `solve.adjoint_missing` before any meshing, and `run.start` raises the same error for a flow-split adjoint case on a host whose default install lacks it. **Stokes bundles the program (G30, decided by the owner 2026-11-15)** as a separate GPL-3.0 program, an aggregate driven only through argv and files (rule 1 is untouched): the agent looks for `adjointFoam` beside the configured install's solvers first and then in `<install>/bin/openfoam-adjoint/` (`stokes_agent.bundled`, the one helper that resolves that folder from where the `stokes` package lives; no machine path). The refusal says to reinstall Stokes or, as the fallback, build it from `of14-adjoint` and copy `adjointFoam.exe` beside the install's solvers. Staging the built `.exe` into the installer waits for the packaging milestone and for G26 (the repository's final name and host); the obligations (licence and notice beside it, an offer of the corresponding source) are in `docs/engineering/dependencies.md` (the generated `THIRD-PARTY-NOTICES.md` gains its section at the packaging step).
6. **Defaults and the gate do not move.** `finite_difference` stays the default gradient for `flow_split`. ADR-0040 decision 6 applies as written, keyed on the part, the quantities, the objective **and the outlet set**: an adjoint row says `gate: verified` only after a passing `shape.check` of the same four in that session, `unchecked` otherwise, and a failed check blocks `gradient: adjoint`. `shape.check` compares the adjoint for the flow split when the program is found and the split takes every outlet. Decision 7's port rule and the secant rule apply unchanged. The panel offers Adjoint for the flow split only when `shape.gradients` says so, labels it experimental, and keeps Finite differences selected when the objective changes to the flow split.
7. **The flow split's J is the desktop's.** `AdjointObjective(objective="flow_split")` computes J from the agent's port flows (`flow_split`), as the finite-difference path does, and carries the fractions, the deviation and the solver's pressure loss in the row; `flow_split_derivative` is the Python mirror of cᵢ, tested against numerical differences, the Euler identity Σ cᵢ Qᵢ = 0 and gauge invariance. The wall formula does not change; where s is read from is decision 8.
8. **The solver's written wall sensitivity comes first (2026-11-15; amends ADR-0038 decision 3).** When the solution time holds `shapeSensitivity` (what `adjointFoam` writes for either objective: the same s, sign and units m²/s³, from OpenFOAM's boundary snGrad with the owner cell's volume centroid) with face values on every wall patch asked for, `job.sensitivity` returns those values in its usual layout (patch by patch, face by face, with the same centres, normals and areas). Otherwise, as for Foundation's `adjointShapeOptimisationFoam`, which writes none, it reconstructs s from U and Ua exactly as before; the two are never mixed in one answer, and a written field with a value that is not finite is an error, not a reason to fall back. The answer's `source` (`solver` | `reconstructed`) is carried to every adjoint row's `detail.sensitivity_source` and to `shape.check`'s `sensitivity_source`, and the Optimise panel shows it beside the best point and the check verdict; an older agent's answer without `source` is labelled `reconstructed`. Why: on the snapped T-junction meshes the reconstruction, whose owner-cell centre is the mean of the face centres, is 15 to 20 % above the solver's own s (ratios against finite differences 1.34 to 1.49, against 1.14 to 1.24 for the solver's; `of14-adjoint/tests/flowsplit.md`). The gate (decision 6) is unchanged: a source label is provenance, not verification.

## Verification plan and measured results (2026-11-15)

The feature is accepted, and this ADR moves to accepted, only when V0 to V3 pass and their tables are written here and in `of14-adjoint/tests/flowsplit.md`. Until then the flow split's adjoint is opt-in, experimental and `unchecked` unless a session's own check verifies it.

| Step | What | Pass | Result |
|---|---|---|---|
| V0 | Regression: `objective` absent, the obstacle case | the same J and `shapeSensitivity` to every printed digit as before | pass: byte-identical to the previous binary (sphere-in-channel; the original obstacle case was not on disk) |
| V1 | Solver level, every flow-split run | solver J = `flow_split` of the agent's flows to 1e-6 relative; Euler sum ≤ 1e-10 (relative); \|Σ phia_out\| / Σ \|phia_out\| ≤ 1e-3 at the end; U, p, Ua, pa reach the residual target; max\|Ua\| steady (last 50 iterations within 1 %) | pass on every run: J to 2e-12, Euler 1e-12, adjoint flux 6e-9, all converged |
| V2 | T-junction (`tools/tjunction_demo.py`): 10 × 10 mm legs, bumps R1 = 3 mm, R2 = 2 mm (R1 = 4 mm if the split is inside 0.48 to 0.52), laminar air 0.2 m/s; `shape.check` on (R1, R2), step 0.25 mm, at 1 mm and 0.5 mm cells | dJ/dR1 > 0 and dJ/dR2 < 0; conclusive (forward and backward within 30 %, signal ≥ 5 noise floors, floor measured); at 0.5 mm both ratios in [0.8, 1.25] and cosine ≥ 0.95; \|ratio − 1\| at 0.5 mm not larger than at 1 mm. Also record `viscousTerm false` and `tangential zero` | fail as written: signs right, cosine 0.9998, ratios 1.16 / 1.24 at 0.5 mm (inside [0.8, 1.25] only just); the second bump's error grows with refinement (0.136 to 0.241) |
| V3 | Manifold (`tools/manifold_demo.py`) at (16, 16, 16): `shape.check` on (h2, h3, h4) ± 0.5 mm, 1 mm mesh; then `shape.optimise` with `gradient: adjoint` | no `wrong_sign`; conclusive rows in [0.8, 1.25]; cosine ≥ 0.95 (two or more conclusive rows); the run does not end `gradient_disagrees`, cycle 1 lowers J above the noise floor, final J within 10 % of 2.02e-4 or at the corner (26, 26, 26); solves and minutes against 16 and 84 | fail: h2 ratio 0.752, h3 0.806, h4 inconclusive (2.1 noise floors); cosine 0.9943 (0.9995 on the two conclusive rows); optimise part not run |

**Result:** V2 and V3 do not pass, so the flow split's adjoint ships `unchecked`-only: experimental in the panel, finite differences the default. Details, including the three opt-in solver options that did not meet the bar, are in `of14-adjoint/tests/flowsplit.md`.

**Phase C (wall gradient on snapped cells, November 2026):** the wall gradient was not the main error. Defaults are unchanged (V0 byte-identical on four cases); `sensitivityWallGradient leastSquares` (`wallCellGrad.H`) is added as an opt-in. It is the most accurate method on an exact-shear Poiseuille test (pipe and a channel inclined 15° to the mesh; within 1.5 % on every mesh, against 6 to 11 % high for `corrected`). Ratios against central finite differences, linearUpwind objective convection plus `leastSquares` (defaults in brackets):

| Case | Ratios (R1 / R2, or h2 / h3) | Cosine |
|---|---|---|
| T-junction 1 mm | 1.117 / 1.071 (1.226 / 1.136) | 0.99995 |
| T-junction 0.5 mm | 1.030 / 1.1005 (1.160 / 1.241) | 0.9999 |
| T-junction 0.33 mm | 1.023 / 1.048 (1.134 / 1.165) | 0.99998 |
| Manifold 1 mm, h2 / h3 | 0.796 / 0.839 (0.752 / 0.806) | 0.9997 |

V2 still fails: |ratio − 1| of R2 grows from 0.071 at 1 mm to 0.1005 at 0.5 mm (it falls again at 0.33 mm, which is not in the gate). V3 still fails: h2 is 0.796, under the 0.8 floor; the `shape.optimise` part was not run. The remaining 3 to 25 % sits in U and Ua themselves (adjoint convection, the ATC term, resolution near small bumps) or in finite differences of a re-snapped geometry; the two were not separated. Decision unchanged: `unchecked`-only, experimental, finite differences the default, ADR stays proposed. Full tables: `of14-adjoint/tests/flowsplit.md`, Phase C.

If V2 passes and V3 does not, the flow split's adjoint ships `unchecked`-only (experimental in the panel, finite differences the default) with the numbers written here. If the adjoint does not converge after the design's cuts (no viscous term, zero tangential, pa relaxation 0.2, a start iteration, a zeroed ATC near the ports), this ADR records the measurements as rejected-for-now and the `shape.optimise` refusal returns; the compile branch and its tests stay.

## Alternatives considered

| Alternative | Why not |
|---|---|
| A user-facing choice of adjoint solver | The objective decides which program can give its gradient; a switch would only offer wrong combinations. |
| Move the pressure loss to `adjointFoam` too | Nothing measured so far moves for the pressure loss; its legacy outlet condition is a known approximation, but changing it is a separate, measured step. |
| Write the objective conditions on outlets outside the split (cᵢ = 0) | Mathematically right, but the solver pushes ν_eff and the ATC switch only to the listed outlets; refused by the owner's decision (G31) until the solver supports it. |
| Leave `adjointFoam.exe` to a manual copy only | Most users would never get the adjoint; bundling a separate GPL program beside a closed-source one is an aggregate, and the owner chose it (G30). The manual copy stays as the fallback. |
| Make the adjoint the flow split's default now | Not before V0 to V3 pass; ADR-0040's rule that an unchecked gradient is labelled stays. |

## Consequences

- Where the host has `adjointFoam`, a flow-split cycle can cost one solve instead of N + 1; until V2 and V3 pass, that is an experiment a user opts into, labelled `unchecked` unless their own check verified it.
- A host without the program (no bundled copy, none beside the solvers) behaves exactly as before, with a sentence that says how to get it. A remote or WSL host gets no bundled Windows binary: its install must carry the program.
- Packaging must stage `bin/openfoam-adjoint/adjointFoam.exe` with its `LICENSE` and `NOTICE.md` and keep the source offer current; that step waits for the packaging milestone (G26 is settled: https://github.com/dhanninacs/of14-adjoint).
- The solver's final dictionary keys are defined in `of14-adjoint/etc/adjointDict`; the compile golden is the contract on the Stokes side and must be updated with it if they differ.
- ADR-0040 is amended (decision 2) by this ADR.
