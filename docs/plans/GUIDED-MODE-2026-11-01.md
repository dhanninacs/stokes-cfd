# Guided mode (Discovery-style set-up on the viewport) — design and briefs, 2026-11-01

Owner's words: "we should be able to fully set up, run and plot results on the display window without touching the tree, like ANSYS Discovery; make this the default mode and the user touches the tree for additional settings. The plotting of results should be as easy as Discovery. The set-up process is not clear enough through the tree, and the set-up panel is cluttered."

What the walkthrough found today (pipe demo, real server on this laptop):
1. The Next-step chip only switches stage; it does not open the thing the text asks for ("pick the bodies and choose them a material in Material…" leads to an empty folder page).
2. Material assignment on a body creates the region, but the mesher still treats that body as `Solid` and reports "domain is 'part' but no domain part is set": the user must repeat the choice in the Mesh stepper. One decision ("this body is the fluid") must set all three: region/material, body role, `mesh_settings.domain_part`.
3. Face picking for inlet/outlet needs the pick-mode menu, a face click and Assign ▾; the boundary value form then shows every parameter of every kind (velocity, components, direction, mass flow, pressure, total pressure…) for a pressure outlet. Only the kind's own parameters belong on the form.
4. Mesh and Run live in different stages with different panels (guided stepper vs Solve page); results need the Results panel tab. Nothing tells the user where they are in the whole flow.

## The product shape

**Guided mode is the default.** A horizontal **flow strip** sits at the top of the viewport (below the top bar, above the model): `Geometry › Fluid › Boundaries › Mesh › Run › Results`. Each step has a state dot (todo / needs attention / done / running) and a one-line hint. The active step opens a **compact floating card** anchored at the top-left of the viewport (where the Field legend sits today; the legend moves below it when both show). Cards are small (max 300 px wide, no scrolling at 900 px tall): 2-5 controls, big primary button, plain words, no internal codes. The tree and Details stay available: a `Tree` toggle in the top bar (and `Ctrl+B`) shows/hides the left slot; in guided mode it starts hidden. Everything a card does goes through the existing API commands (no new model types). **Full mode** = today's layout (tree visible, Details beside it); the strip stays visible in both modes.

Step cards:
- **Geometry**: Import CAD button (opens the existing picker/upload; drop zone text stays), then the bodies as rows with a role chip: `Fluid` / `Solid` / `Leave out` (role = mesh body role; `Fluid` also sets `mesh_settings.domain_part` and offers the material). Default: a body named like `fluid|air|water|domain` is Fluid; a single body is Fluid; else all Solid until the user picks. Done when at least one Fluid body exists.
- **Fluid**: the fluid body's name, a material quick-pick row (`Water`, `Air` from the built-in library, `Browse…` for the existing library dialog) and the chosen material with density/viscosity readout. Choosing a material assigns it to the fluid body (existing `material.add_from_library` + region assignment path used by the Material menu). Done when the fluid region has a material.
- **Boundaries**: instruction "Click a face of the fluid, then choose what it is"; picking a face in the view (the card switches the pick mode to Face while open and restores it on leave) shows chips `Inlet` (velocity inlet, value field `m/s` inline), `Outlet` (pressure outlet, `Pa`, default 0), `Wall`, `Symmetry`; the list of boundaries assigned so far with their colour swatch, kind and value, each with an edit (inline value) and remove (x); a line "N faces not assigned yet → they become walls at meshing" (true today: unassigned faces go to the default wall patch; keep that behaviour, and show the count from `setup.check`). Done when the set-up check is `ready`.
- **Mesh**: a size control (`Coarse / Medium / Fine` segmented control mapped to a base size from the fluid body's bounding box: ~1/20, 1/40, 1/80 of the smallest box side, shown as the length it maps to), `Boundary layers` switch (the existing setting), the `Generate` button with progress, then `N cells · quality ok` and a `Show mesh` toggle (existing mesh display). Done when a fresh mesh result exists.
- **Run**: `Iterations` (default from settings), `Run`/`Stop`, a live residual sparkline (reuse ResidualPlot in a compact height), state line `converged in N iterations · t s`. Done when the run is done or done_unconverged.
- **Results**: field chips `Velocity` / `Pressure` (U_mag, p), the legend (existing FieldLegend inside the card or directly under it), switches `Mid-plane slice`, `Arrows` (if the existing arrow layer is cheap to toggle), `Probe` (existing probe), and `Report…` (existing run.report). Picking a field colours the surfaces (existing FieldsController). The pressure drop readout (inlet p_mean − outlet p_mean) when monitors exist.

The strip's step states come from one pure model (`web/src/guided/guidedModel.ts`): inputs are the tree, `store.setup` (setup.check reply), mesh status, `store.run`, `store.results`; output is `{steps: [{id,label,state,hint}], active}`. Tested with vitest fixtures for: empty project, imported but no fluid, fluid without material, boundaries missing, ready, meshed, running, done, results loaded.

## Brief A (front end, Sonnet): the flow strip, the cards, the mode switch
Files: new `web/src/guided/` (`GuidedStrip.tsx`, `GuidedCard.tsx`, one `steps/<Step>Card.tsx` per step, `guidedModel.ts` + test, `guided.css`), mount in `App.tsx`/`Viewport.tsx` overlays, a `guided` flag in the workspace document (`workspace/defaults.ts`: `mode: "guided" | "full"`, default guided; persisted like other workspace fields), the `Tree` toggle button in `app/TopBar.tsx` items (and `Ctrl+B`). Reuse existing hooks/commands: `useAssignMenu`/`assignCommand` (boundary.assign with kind/target/values), `useMaterialMenu`/`libraryCommands`, `generateMesh`/`useGenerateState`, `pressRun`/`useRunButton`, `showResults`/`chooseField`, `FieldLegend`, `ResidualPlot`. Do not change the Python side; where the card needs "one decision sets role + domain_part + material", issue the existing commands in sequence (`mesh.configure` values for body roles and `domain_part`: read `panels/meshTaskPages/` to see exactly what the stepper's Fluid/Solid/Hole buttons send). Theme tokens only. Keep the existing panels untouched except mounting points. Gates: `npm run typecheck`, `npx vitest run`, `npm run build`. Report with file list and what is not done.

## Brief B (front end, Sonnet): uncluttered boundary form and the Fluid decision from the tree path
1. `panels/ConditionPanel.tsx` + `panels/conditions.ts` (`formFields`): show only the parameters the chosen kind uses (the catalogue's per-kind parameter list arrives with `boundary.kinds`; `velocity_inlet` → velocity (+ direction choice), `pressure_outlet` → pressure, `mass_flow_inlet` → mass flow, wall → nothing or the wall options); the other parameters go under a collapsed `More…` only if the kind lists them. Same filter for the Details boundary page (`SettingsNodeFields`/`PropertiesPanel` path for `boundary` nodes). Tests for the field selection per kind.
2. `panels/MaterialMenu.tsx` (the on-body Material ▾ and the tree's material assignment): after a material is assigned to a body that is not yet the fluid, also send the mesh body role `Fluid` and `mesh_settings.domain_part` for that body (same commands the Mesh stepper's "Fluid" button sends; read `panels/meshTaskPages/`). If the body is already the domain, do nothing. Test the command sequence with the scripted client.
3. `app/NextStep.tsx`: when the next step is "define" it must open the Boundaries card in guided mode (export a `openGuidedStep(id)` from `guided/` that Brief A provides; until it exists, open the Conditions panel as today). No other NextStep changes.
Gates as A. Do not touch files Brief A owns (`web/src/guided/**`, `App.tsx`, `Viewport.tsx`, `TopBar.tsx`, `workspace/defaults.ts`).

No tree interaction. Then switch to Full mode and confirm the tree shows the same state.
