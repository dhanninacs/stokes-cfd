Stokes

CAD in. Results out.

A desktop GUI for OpenFOAM 14 on Windows and Linux. Import a STEP file or model the part in the app, preview the flow on the GPU, then mesh it, run it and read the results, all in one window.

Install Source on GitHub

Free for noncommercial use. Pre-alpha, and runs from source for now.

One case, start to finish.

Two streams of water at different temperatures meet in a bend. Half the elbow is modelled, with a symmetry plane. Every picture here is that case.

  1. Import. Open a STEP file and mark the body as fluid.

  2. Boundaries. Pick a face, call it an inlet, type 0.4 [m/s].

  3. Mesh. Choose a mesher and a cell size. Quality is checked when it finishes.

  4. Run. Residuals stream in as it solves. A run that misses its target says so.

  5. Results. Slices, streamlines, iso-surfaces, probes and plots.

Values that change in time.

An inlet, an outlet or a wall can follow a table, a sine or a pulse instead of a constant. Run it transient and the results get a time slider. Here the ball in the duct again, with air pulsing in at 0.3 ± 0.15 m/s, twice a second.

A profile, with a plot.

Pick a form and type its values with their units. The plot shows what the run will see. A table can be pasted from a spreadsheet, and units in its header are read. The setup check says when a run is too short or too coarse in time for the profile.

How often to save.

The Run card suggests Save every from the profile, about 20 frames a period, and says how much time was simulated. This run: 1 s in 2,452 adaptive steps, 3 min 45 s on 8 cores, 50 frames saved.

Play it back.

The time slider and Play drive the picture, the pressure drop, the Monitors table and the Streams. History leaves out the start-up spike by default. Full mode's Results panel has its own slider.

Fast meshing.

One switch gives snappyHexMesh two cells between refinement levels and shorter snapping and layer loops: about 17 % fewer cells and quicker meshing, at a slightly coarser mesh. This one, with three boundary layers: 72,618 cells in 23 s on 8 cores, quality checked.

See the flow before you mesh.

Fast mode is a lattice-Boltzmann preview that runs on your graphics card. It draws the flow in a plane while it solves. Change an inlet speed or raise the fidelity and the picture follows, live. It is a quick look, not a sign-off. For the answer, Stokes runs the same case in OpenFOAM.

A plane, a legend and the numbers.

The panel shows the pressure drop and the flow in and out as they settle. Five fidelity levels set how many cells span the passage. It needs a GPU, and for now it works on parts modelled in the app, not on imported CAD.

Same case, two solvers.

The ball in the duct, air in at 0.05 m/s. Speed in the middle plane, with the same view, colour map and range on both sides.

Pressure drop
9.17 mPa in Fast mode, 9.56 mPa in OpenFOAM solved to a residual of 1e-5. They are 4 % apart.
Time to a picture

Where it stops
This is a simple laminar case, and one measurement on one computer. In passages only a few cells wide the preview reads high: on the gyroid exchanger below, about 2 to 3 times the solved pressure drop and heat. Use it to look, and OpenFOAM to decide.

Model it in the app.

No CAD file? Build the part here. Start from a box, a cylinder or a sphere, or sketch a profile and pull it into a shape. Join, subtract and intersect bodies. Fill one with a gyroid, Schwarz P or diamond lattice. Sizes are values with units, so they can be changed later.

Shapes and booleans.

A ball subtracted from a box leaves a ball-shaped hole. The section view cuts the body so you can see inside it.

Lattices.

A section through an example gyroid plate heat exchanger. The gyroid wall keeps two channel networks apart, one for each stream.

Heat exchangers: two streams and a solid.

An example gyroid plate heat exchanger, set up as conjugate heat transfer: a hot stream, a cold stream and the solid between them, meshed as one case and solved together in OpenFOAM.

Temperature on a plane through the core.

Hot comes in at 350 K on the left, cold at 300 K on the right. The two never mix; the heat crosses the gyroid wall.

The Streams table.

The Results card lists each stream’s flow, pressure drop, temperature in and out, and heat. Here the hot side gives up 117.5 W and the cold side takes 107.1 W. They agree to 8.8 %, and the card says so. This run stopped at its 500-iteration limit, not converged.

Streamlines that follow the walls.

Lines seeded at the inlets slide along a wall they meet and carry on, so they run the whole path through the narrow passages. Coloured by temperature.

Fast mode shows where the heat goes. It does not size the exchanger.

This is the preview of the same model. The picture is useful for checking the set-up. The numbers are not: on a core this fine it reads about 2 to 3 times the solved pressure drop and heat. The figures above are from OpenFOAM.

Change a value.
The case follows.

Stokes writes the OpenFOAM case from the model you build. Raise an inlet speed or shrink a cell size and the dictionaries are written again, so there is nothing to hunt for in system/ and nothing to keep in sync by hand.

Mesh with boundary layers.

One switch adds three layers of thin cells along every wall, where the velocity changes fastest. This is a snappyHexMesh hex mesh cut through the ball. The section view shows the cells, and the layers hugging the ball and the duct walls.

Meshes you can check.

snappyHexMesh, cfMesh, blockMesh, or Gmsh for tetrahedra with prism layers. This elbow mesh has 81,749 cells and passed its quality check.

Results in the same window.

Streamlines seeded from the inlets, coloured by speed. Slices, iso-surfaces, probes and line plots sit next to them.

Three styles, each in light and dark. The video above uses Cupertino light.

Tech specs.

OpenFOAM
Foundation 14, from openfoam.org. The openfoam.com line is not supported yet.
Windows 10 and 11
Yes, natively, with no WSL. OpenFOAM comes from FoamWin. The most tested platform.
Linux
Yes, with the official OpenFOAM 14 packages. Less tested than Windows so far.
macOS
Not supported.
Geometry
STEP import through Open CASCADE. IGES and BREP from the command line. Or model in the app: primitives, sketches, booleans, patterns, offset and shell, and gyroid, Schwarz P and diamond lattices.
Meshing
snappyHexMesh, with a Fast profile for about 17 % fewer cells, blockMesh, cfMesh hex-dominant, tetrahedral, polyhedral and poly-hexcore, and Gmsh tetrahedra with prism layers. 2D planar and axisymmetric. A section view through the cells.
Physics
Steady or transient. Laminar, k-ε and k-ω SST, with the energy equation. Conjugate heat transfer across fluids and solids. Parallel runs over MPI.
Boundaries
Inlets, outlets, walls and symmetry planes. A value can be constant or follow a table, a sine or a pulse in time, written as an OpenFOAM 14 time function.
Solvers
OpenFOAM’s foamRun and foamMultiRun, and coupledSimpleFoam as an optional coupled engine. Under-relaxation factors can be set for steady runs.
Fast mode
A lattice-Boltzmann preview on the GPU, drawn live in a plane, with WALE and Vreman closures, a warm start from a coarser lattice and 16-bit storage for large lattices. A quick look, not a sign-off. Needs a graphics card, and a part modelled in the app.
Results
Slices, clips, iso-surfaces and 3-D contours, wall-following streamlines, vectors, probes, line plots, a Streams table for flow, pressure drop and heat, reports and picture export. A time slider and Play for transient runs.
Units
Every value carries a unit. Type 2 [m/s] or U_in * 1.5.
Automation
The window, the stokes command and a local server share one API, so scripts and LLM agents can drive a case.
Installer
Not yet. Stokes runs from source with Python 3.13 or 3.14; on Windows one setup script does it. Version 0.0.1.dev0, pre-alpha.
Licence
Free for noncommercial use under PolyForm Noncommercial. Source-available, not open source. Commercial licences on request.

Run it from source.

You need Python 3.13 or 3.14, Node.js 22.12 or newer, Git, and OpenFOAM 14. The full guides cover every step and the usual snags.

Windows

One script installs Stokes, builds the front end and, if this computer has no OpenFOAM, offers to download FoamWin and checks it against its published SHA-256. MS-MPI if you want more than one core.

git clone -b windows https://github.com/dhanninacs/stokes-cfd.git
cd stokes-cfd
powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1 -Shortcut

It leaves a Stokes shortcut on the desktop. The guide has the same steps by hand.

Linux

The official openfoam14 package on Ubuntu 22.04 or newer, plus cfMesh if you want it.

git clone -b linux https://github.com/dhanninacs/stokes-cfd.git
cd stokes-cfd
python3.13 -m venv .venv
.venv/bin/pip install -e ".[agent,server,ui,cad,extract,explore,materials]"
cd web && npm ci && npm run build && cd ..
source /opt/openfoam14/etc/bashrc && .venv/bin/python -m stokes.app

Questions.

Does it need WSL on Windows?

No. It drives FoamWin, a native Windows build of OpenFOAM 14, directly. There is no WSL, virtual machine or Docker layer.

Can I trust Fast mode’s numbers?

Treat it as a preview. On a ball in a duct its pressure drop was 4 % from OpenFOAM’s. On a fine gyroid core, where the passages are only a few cells wide, it read about 2 to 3 times the solved pressure drop and heat. Run the case in OpenFOAM before you rely on a number.

Can it run transient cases?

Yes. Switch the Run card to transient, and give an inlet, outlet or wall a value that changes in time if the case needs one: a table pasted from a spreadsheet, a sine or a pulse. The results get a time slider and Play.

Does it replace OpenFOAM?

No. You install OpenFOAM separately. Stokes writes the case, runs your OpenFOAM tools as separate processes and reads the results back. It never bundles or links OpenFOAM.

Can I use my own OpenFOAM cases?

Yes. Import an existing case or one of the OpenFOAM tutorials, edit its files as text inside the app, and run it.

Can I run it on a remote machine?

Yes. Start python -m stokes.server there and open it through an SSH tunnel. The server only listens on 127.0.0.1 and asks for a one-time token.
